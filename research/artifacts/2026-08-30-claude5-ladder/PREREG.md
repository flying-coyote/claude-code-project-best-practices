Written **before any arm was run or scored** (2026-08-30). Fixed in advance so the analysis
cannot be chosen after seeing the data.

`research/artifacts/2026-07-18-realistic-ladder/` unchanged — same rule bank, same seed

## Gates (an ungated arm is not evidence)

Every arm must pass all of:
1. **Per-turn served model** — every assistant turn carries the arm's expected model string;
   any other string (including `<synthetic>`) fails the arm.
2. **Guide Read** — treatment arms must show a Read of their own rung's guide; baseline arms
   must show no guide Read at all (contamination check).
3. **No compaction** markers in the transcript.
4. **Effort** — recorded per turn and reported; 2026-07-18 ran at `xhigh`.
5. **Deliverable completeness** — all three files present; incomplete arms are excluded and
   reported separately (the 2026-07-18 usage-limit exclusions are the precedent).

## Primary analysis (fixed now)

Identical to `aggregate_ladder.py`'s pre-registered analysis:

- **informative rule** := satisfied in ≤ 2 of the baseline runs;
- **primary metric**: adherence = SAT/(SAT+VIOL) over the rung's informative rules;
- **secondary**: adherence over informative CORE25 (shared by every rung); raw adherence;
- NA excluded from denominators; ERR reported separately and excluded.

**Two informative sets are reported, both fixed in advance:**
- **session-relative** — computed from *this* run's 9 baseline arms (3 per model, pooled).
  This is the primary, because the 2026-07-18 record establishes the informative set is
  session-relative (agents inherit the ambient CLAUDE.md).
- **frozen 2026-07-18 set** — the 78-rule informative set from the prior run, reported
  alongside for cross-date comparability.

## Declared in advance: what would count as a result

- A **ceiling** (all arms 1.0) replicates the prior ceiling on a new model generation and
  **discharges nothing** about the ~150 cap. Three prior rounds hit ceiling; a fourth is
  descriptive only, and will be reported as such in exactly those terms.
- A **sub-ceiling score** is interpretable only if the baseline positive control violated
  rules in the same run (it does: ~79/run at 2026-07-18) *and* the specific violated rule
  survives an adjudication check against the rule's prose, not the regex's literalism.
- Any between-model difference is reported as **adjudication-dependent** unless it survives
  both the strict and lenient reading of the rule sentence involved.

## Known limits, declared now

- One seed-locked rendering per rung, so rung size is confounded with sentence adjacency
  (inherited from 2026-07-18).
- Surface-checkable constraints only; semantic, conditional and genuinely conflicting rules
  are outside this instrument's reach. This is the residual the Fable-failure-capable design
  is meant to address, and it is **not** addressed by this run.
- `content-stdlib` is the one rule whose competing phrasing the prompt plants; it is
  pre-declared here as adjudication-sensitive, both readings to be reported.
